# 产品图片加载与缓存验收（Issue #121）

## 自动化覆盖

- 公开产品图片使用 `/api/v1/public/product-images/{fileId}/{variant}/{version}`；版本来自原文件 SHA-256，旧数据缺少哈希时在首次产品查询中自动补齐。
- `CARD` 最长边不超过 640px，目标不超过 300KB；`DISPLAY` 最长边不超过 1600px，目标不超过 1MB；`ORIGINAL` 保留原文件。
- 响应包含正确的 `Content-Type`、`Content-Length`、`ETag` 和 `Cache-Control: public, max-age=31536000, immutable`；匹配 `If-None-Match` 时返回 304。
- 每次公开读取都校验文件仍绑定未删除且已上架的产品。下架、删除、未绑定以及订单/施工/评价/临时文件无法通过该公开入口读取。
- 派生失败时回退原图并记录仅含文件 ID、变体和异常类型的安全日志。

对应集成测试：`ProductImageVariantIntegrationTests`。测试还用三张高分辨率图验证尺寸和体积上限，并覆盖旧图片哈希回填、稳定 URL、换图换 URL、WebP 回退和私有文件隔离。

## 小程序人工验收

本机没有微信开发者工具和真机环境，以下项目按约定保留为人工验收：

1. 清空小程序缓存后进入首页，确认产品请求不等待分类请求；首屏只请求可视区域及前置少量 CARD 图片。
2. 快速上下滚动，确认临近视口才发起图片请求，图片区域尺寸稳定，无明显跳动；断网后恢复并点击失败区域可重试。
3. 进入产品详情，确认首张 DISPLAY 优先展示，未切换的轮播图及未临近的详情长图不提前请求。
4. 点击当前图片后出现“正在加载原图”，仅此时请求对应 ORIGINAL；加载失败有提示且可再次点击。
5. 在微信开发者工具 Network 或代理中记录首次响应为 200，刷新/重进后命中本地缓存或以 `If-None-Match` 获得 304，且 URL 在文件不变时保持一致。
