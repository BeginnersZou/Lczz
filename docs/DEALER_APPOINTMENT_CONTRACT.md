# #100 经销商预约安装：前端实现与接口提案

状态：2026-09-07 前端开发，后端同事负责接口和数据迁移。以下新增接口、枚举与字段是待确认契约，不能视为已上线能力。
基线：dev 98577654。前端分支：codex/dealer-booking-100。

## 页面与交互

1. 小程序首页仅在 `/auth/info` 成功返回 DEALER 角色时显示“预约安装”。直接打开页面也重新检查角色；游客仍可自由浏览其他页面。
2. 使用原生白色导航栏，表单分为“安装需求”“客户与上门地址”“现场附件”。任务类型沿用后台四项；描述占位必须为“例如品牌、主机信息、内机信息、主内机控制器、水箱等信息”。
3. 不收集预约时间和师傅，不展示支付入口。描述、姓名、手机号、省市区、详细地址必填；附件选填，沿用订单图片上传（最多9张，每张10MB），不擅自扩展可执行文件等类型。
4. 每张图片独立标识、上传进度、失败重试及移除。未全部上传成功不能提交。仅使用返回的文件ID，不把本地临时路径提交为附件。
5. 成功显示订单编号与“管理员将核对需求、安排上门时间并指派师傅”。经销商提交人不因此获得客户订单详情/评价权限。
6. 网络超时或5xx时冻结原表单与请求ID，以相同请求核实结果。不得假报成功或以新ID自动重试。404显示服务未开放，401/403停止继续提交。
7. PC 列表、详情与编辑页统一展示订单来源、提交经销商。待派单订单通过“完善并派单”复用编辑页，管理员补充时间和师傅。描述上限1000字、姓名上限64字，与预约字段和现有Java校验对齐，避免编辑回显截断。

## 新增接口（待后端确认）

`POST /api/v1/dealer/appointments`，Bearer Token，只允许 DEALER。

```json
{
  "requestId": "客户端生成且失败重试复用的唯一ID",
  "taskType": "空调安装",
  "description": "安装需求（1至1000字）",
  "customerName": "客户姓名（1至64字）",
  "customerPhone": "11位大陆手机号",
  "addressArea": ["省名称", "市名称", "区名称"],
  "addressDetail": "详细地址（1至500字）",
  "fileIds": [123, 124]
}
```

`taskType` 与现有 PC 表单一致：空调安装、空调维修、空调清洗、空调移机。
小程序 region picker 返回地区名称；后端需复用现有地址名称解析规则，明确直辖市/无区县行政区的兼容策略。

返回沿用 `{code:200,message,data}`，data 至少包含：

```json
{
  "id": 123,
  "orderNo": "服务端生成的订单号",
  "statusCode": "PENDING_ASSIGNMENT",
  "orderSource": "DEALER_APPOINTMENT"
}
```

失败：400/422校验未通过；401未登录；403非经销商或账号停用；409幂等键关联内容冲突；5xx结果不确定。同一经销商、同一 requestId、相同内容再次请求必须返回原订单，不重复创建、绑定附件或发短信。

## 现有接口增量（待后端确认）

`GET /orders/list`、`GET /orders/detail/{id}`、`GET /admin/orders/{id}` 的 order 对象统一新增：

- `orderSource`: `ADMIN` / `DEALER_APPOINTMENT`，历史无字段前端暂按“后台创建”展示。
- `dealerUserId`: 服务端从认证用户确定，不接受客户端指定。
- `dealerName`: 提交经销商展示名称，仅管理员可读；不返回额外私人资料。
- `statusCode`: 建议新增 `PENDING_ASSIGNMENT`（待派单），避免未指派订单冒充“待上门”。
- 未安排时 `orderStartTime`、`orderEndTime` 为 null，`selectedMasterList` 为空数组。

`PUT /orders/{id}`：管理员补充时间与师傅成功后，待派单转待上门；其余校验沿用现有规则。来源和经销商不可通过编辑表单篡改。
前端暂未加入待派单服务端筛选项，待后端明确支持该枚举后再开放。

## 后端交付与安全边界

- 新建预约、绑定/复用客户、绑定全部附件、记录来源与状态历史必须原子提交。
- 经销商不能调用管理员创建/修改/派单接口，不得伪造经销商ID、客户ID、师傅ID、来源或状态。
- 文件只接受当前用户持有、有效、未绑定的临时图片，校验类型、数量、大小及所有权。服务端在预约事务内绑定，不能为支持预约而开放所有订单附件写权限。
- 新增待派单状态后需同步状态机、管理员编辑/取消、统计、导出与空师傅兼容。现有 `OrderService.update` 对空师傅拆箱、`assign` 对空师傅调用 equals，均需修正。
- 客户手机号复用现有绑定规则；相同手机号不能重复建立客户主体。提交经销商与最终服务客户是不同关联。
- 对应 schema 迁移由后端 Flyway 提供，前端不改数据库。
- 事务成功后调用 #101 已提供的 `queueDealerAppointmentCreated`；发短信失败不得引导用户重复新建订单。
- 原生返回/退出时前端不持久化客户姓名手机号等草稿；未绑定上传由后端过期回收。请求结果未知时不得删除可能已绑定的文件。
