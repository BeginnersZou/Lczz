# 施工进度通知与客户确认

师傅成功提交一条施工进度后，系统为订单的客户联系电话创建一条短信通知。多张附件属于同一次提交；不会按附件数发送通知，也不会发给管理员或经销商。管理员修改历史施工内容不触发这条通知。

客户在订单详情可逐条点击“确认本次进度”，核对说明和附件后通过二次弹窗确认。页面显示待确认、已确认或待重新确认，以及确认时间。后台订单详情和修改页也展示确认结果。

## 与订单状态的关系

进度确认仅记录客户认可本条施工内容，不改变订单状态、订单版本或施工封存状态。师傅不需要等待客户确认，仍能按原有权限继续上传进度。

“确认订单完成”保留独立入口和二次弹窗，不要求先确认全部进度。客户完成订单后，原有施工封存规则仍限制师傅继续修改或上传；尚未确认的历史进度可以补确认，不会重新打开订单。已作废订单不能确认进度。

## 权限与内容版本

只有当前订单绑定的客户可以确认。管理员、安装师傅、经销商以及其它客户无确认权限；具有上述管理角色的混合角色账号也不能作为客户确认。

列表接口返回 `contentVersion`，由进度类型、说明和附件文件 ID、用途、排序计算，不包含会变化的文件访问 URL。确认请求必须携带客户当时查看的版本：

```http
POST /api/v1/orders/{orderId}/progress/{progressId}/confirm
Content-Type: application/json

{"contentVersion":"列表返回的64位内容版本"}
```

旧 `/api/orders` 前缀同样支持。内容已经变化时返回 409，客户需重新查看后确认；重复确认同一内容不重复写入记录。管理员修订说明、增删或调整附件后，旧确认不代表新内容，页面显示待重新确认。每次有效确认保存客户、时间、内容版本及说明/附件快照，保留历次记录。

## 提交重试与短信

进度提交接口增加可选的 `requestId`（最多 64 字符），兼容现有不带该字段的调用。新版小程序为每次提交生成标识；请求结果未知时保留原说明、附件和标识，重试不重复创建进度或发送短信。同一标识换用不同内容返回 409。旧客户端不提供标识时不具备这项重试去重能力。

短信沿用事务内通知记录和提交后的异步发送机制。进度保存回滚时不会通知。发送失败由现有调度重试；通知记录使用 `PROGRESS_SUBMITTED` 事件和 `WORK_ORDER_PROGRESS` 业务类型，模板参数为 `orderNo`。未启用短信、缺少模板/凭证或客户手机号不合法时，记录为 `SKIPPED` 并保留原因，不影响施工提交。

## 发布要求

需要更新后端、小程序和后台管理系统。后端启用 Flyway 时执行 `V15__progress_customer_confirmation.sql`，增加进度提交/确认字段及确认历史表；不会将历史进度自动标为已确认，也不会改写订单状态。若生产禁用 Flyway，先按数据库发版流程应用 V15，再启动新版后端。

新短信场景使用独立配置 `SMS_PROGRESS_SUBMITTED_TEMPLATE_CODE`，不复用派单、预约或耗材下单模板。实际模板 CODE、服务器配置和重启步骤在发版教程中提供；未配置时进度仍可提交与确认，短信记录显示模板未配置。

验收时检查：多次进度未确认仍能提交；单条确认后订单状态不变；最终完成无需全部确认；重复请求不重复通知；他人不能确认；管理员改动附件或说明后旧版本确认被拒绝。
