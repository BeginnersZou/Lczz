# 客户确认订单完成（Issue #99）

订单流程为：待上门 → 处理中 → 绑定客户确认完成 → 待评价 → 已评价。“已完成”包含待评价和已评价，客户确认无需管理员审核。

## 操作与兼容

- 小程序只对订单绑定的客户或经销商账号展示“确认订单完成”；仅处理中可操作，弹窗内容为“是否确认订单已完成”。取消不发送请求，重复点击只产生一次请求。
- 确认后显示确认时间及评价入口，师傅只保留历史施工查看。师傅端原“完工提交”入口已移除；旧客户端请求完工接口返回 410，不推进状态。
- 确认后禁止追加施工和修改施工附件，包括文件上传时直接关联、绑定、解绑，以及管理员附件操作。上传未关联的临时文件不会改变施工记录。
- 刷新、返回页面或遇到状态冲突时重新读取订单，过期的师傅录入入口随之隐藏；后端始终检查真实状态。
- 后台列表、详情、CSV 导出显示客户确认时间；`COMPLETED` 筛选汇总待评价及已评价，仍可精确选择二者。
- 确认时间和确认人来自状态历史。历史师傅完工保持可读，不补造客户确认；评价不会覆盖确认时间。保留既有取消规则，无新增表或迁移。

接口及响应错误见 [后端 README](../backend/README.md)，业务约束见 [开发规范](DEVELOPMENT.md)。

## 自动验证

1. 在 `backend` 使用 Java 21 执行 Maven Wrapper `verify`。`OrderConfirmationIntegrationTests` 覆盖双前缀角色/绑定权限、状态限制、历史兼容、确认及评价、确认时间稳定、筛选、封存后的写入拒绝和并发确认/施工。
2. 在 `frontend/admin` 执行 `npm ci`、`npm run build`。
3. 在仓库根执行 `node scripts/verify-order-confirmation.cjs`。脚本使用上一步已安装的 Vue 编译工具，编译微信与非微信条件分支，并使用真实 Vue 响应式逻辑和模拟的 uni-app 生命周期/API 检查四角色、五状态、二次确认、取消/重复点击、网络错误、409 刷新、权限恢复和师傅提交期间订单被确认的情况。

组件验证不替代微信开发者工具和真机验收。人工验收应使用一名绑定客户、一名其他客户、一名指派师傅和管理员，完成以下流程：

1. 师傅提交多条施工进度及图片/视频，客户查看记录并取消一次确认，订单仍为处理中。
2. 客户再次确认完成；师傅返回详情后录入入口消失，原文字及媒体正常查看；客户可继续评价。
3. 后台查看确认时间和全部施工记录；“已完成”筛选及导出同时包含待评价、已评价订单；精确筛选仅返回对应状态。
4. 切换至未绑定客户或管理员账号，不出现客户确认入口；查看历史完工订单时不展示伪造的客户确认时间。
