# 新增可登录后台的管理员（Issue #111）

在后台“用户管理 → 新增用户”选择“管理员”，填写原有用户资料、手机号，以及登录账号、登录密码、确认密码。创建成功后，新管理员可直接在现有后台登录页登录。其他角色继续使用手机号预创建与小程序绑定流程。

## 接口约定

`POST /api/v1/users`，兼容 `POST /api/users`，仅已登录且有效的管理员可以调用。

| 字段 | ADMIN | 其他角色 |
| --- | --- | --- |
| `nickname`、`phone`、`role` | 按原契约必填 | 按原契约必填 |
| `username` | 必填；4–64 位英文字母、数字、点、下划线或短横线；去首尾空格、转小写后保存 | 省略或 null |
| `password` | 必填；至少 8 个字符，UTF-8 编码最多 72 字节；不修剪空格 | 省略或 null |
| `confirmPassword` | 必须与密码完全一致 | 省略或 null |

密码长度的字节上限与 BCrypt 一致，例如 72 个 ASCII 字符或 24 个汉字。数据库复用 `sys_user.username`、`password_hash` 和用户名/手机号唯一索引，无新增迁移。账号唯一性包括已停用或逻辑删除用户占用的账号。

创建用户、分配 ADMIN 角色和成功审计在同一事务中完成。只保存 BCrypt 哈希，密码及哈希不进入创建响应、列表、详情或审计。创建完成不会切换当前操作管理员的会话。登录继续使用 `/api/v1/auth/login`，原有停用、黑名单和角色限制持续生效。

| HTTP / 错误码 | 原因 |
| --- | --- |
| 400 `INVALID_ADMIN_USERNAME` | 管理员登录账号缺失或格式错误 |
| 400 `INVALID_ADMIN_PASSWORD` | 密码缺失、空白、过短或超过字节限制 |
| 400 `PASSWORD_CONFIRM_MISMATCH` | 确认密码缺失或不一致 |
| 400 `ADMIN_CREDENTIALS_NOT_ALLOWED` | 为其他角色设置登录凭据 |
| 400 `VALIDATION_ERROR` | 原有资料校验或请求字段长度校验失败 |
| 409 `USERNAME_ALREADY_EXISTS` | 账号已被占用，包含大小写差异 |
| 409 `PHONE_ALREADY_EXISTS` | 手机号已被占用 |
| 409 `USER_ALREADY_EXISTS` | 并发创建触发账号或手机号唯一约束 |
| 401 / 403 | 未登录、无管理员权限或账号不可用 |

本功能不为历史管理员自动生成凭据，也不新增他人密码重置能力。现有“编辑自己的管理员资料并校验原始密码后修改密码”流程继续可用。

## 验证

- 在 `backend` 使用 Java 21 执行 Maven Wrapper `verify`。`AdminCreationIntegrationTests` 验证双前缀创建/登录、权限、错误输入、密码字节边界、重复/并发创建、事务完整性、凭据不泄露、停用/黑名单/角色撤销和其他角色预创建兼容性。
- 在 `frontend/admin` 执行 `npm ci`、`npm run build`。
- 浏览器验收：新建管理员 → 空值/密码不一致提示 → 正常创建 → 原账号仍保持登录 → 新会话用新账号登录并访问用户管理 → 重复账号显示冲突；角色切换与关闭弹窗清理凭据，其他角色请求不带密码字段。
