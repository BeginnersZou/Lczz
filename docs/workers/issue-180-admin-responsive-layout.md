# Issue #180 Worker：PC响应式布局

基线 origin/dev@ea5c3ece；分支 codex/admin-responsive-layout-20261014。

根因：Layout把路由内容固定最大1480px并居中；订单、耗材、用户和备货表格把整个组件设为超宽最小尺寸，导致外层滚动和固定列行为冲突。编辑页同时有多层居中规则。

设计：
- 小屏901–1279px默认图标侧栏64px，内容间距20px；≤900px抽屉导航，间距16px。
- 中屏1280–1919px导航216px，内容间距24px。
- 大屏≥1920px导航232px，内容间距32px，列表与工作台使用完整可用宽度。
- 表单和详情最多1280px、左对齐，与列表内容入口一致；筛选、页头操作、分页和表格按可用宽度适配。
- 菜单用户偏好持久化，移动抽屉始终完整展开，跨断点恢复正常状态；工作台图表随实际容器变化重新适配。

仅改变视图和导航响应式行为。已核对业务接口及权限，无后端契约和业务规则变更。

验证：真实浏览器在375、900、1024、1280、1366、1920、2560、3840px检查侧栏到内容的间距、根页面溢出、内部表格滚动、固定操作列、表单及菜单跨断点。截图和最终结果在PR记录。

完成记录：浏览器覆盖9种宽度（另含截图对应3816px）×10个页面，共90个组合，通过列表宽度、筛选和动作可达性、表格首列/横向滚动、表单左对齐、用户弹框及菜单跨断点检查；验证折叠菜单后图表随容器重新适配。窄屏解除操作列固定，防止遮挡首列。5个现有PC流程验证脚本及4项PC测试通过，生产构建通过。

实测订单内容入口：1024px屏幕x=84（64px侧栏+20px间距）；1366px x=240（216+24）；1920–3840px x=264（232+32）。3816px时列表宽度3520px，没有额外居中留白。

浏览器验证脚本：scripts/verify-admin-responsive-layout.cjs。启动独立Vite端口5187，提供playwright-core及匹配Chromium；通过LCZZ_PLAYWRIGHT_MODULE、LCZZ_BROWSER_EXECUTABLE指定运行时，LCZZ_QA_OUTPUT指定报告目录。所有API为仅GET的测试数据，截图不是生产订单。

本地截图及layout-results.json位于 .runtime/admin-layout-180（工作区根目录）。
