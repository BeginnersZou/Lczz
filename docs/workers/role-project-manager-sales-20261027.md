## 已确认的产品规则

- 用户只能拥有一个角色。新增 `PROJECT_MANAGER`（项目经理）和 `SALES`（销售员），均由管理员在 PC 用户管理中新增或指定。
- 项目经理**仅通过小程序手机号登录**，可查全部订单及允许公开的订单详情；不能有任何写操作。搜索、筛选、翻页、查看详情属于只读交互。误触写入口弹出“无操作权限”，服务端仍必须返回 403。
- 销售员可在小程序创建预约；**经销商和销售员的小程序预约页均新增“销售人员”下拉列表**，列出平台现有可用销售员供选择，并可清空、不选。管理员在 PC 创建订单时同样可选填。销售员自建订单也不自动绑定本人；创建人和指定销售员是不同概念。
- 销售员只能查看自己创建的订单，或任何创建者明确指定给自己的订单。即销售员 A 创建并指定销售员 B 时，A、B 都能查看；未指定时仅 A 可按创建人身份查看。经销商仍只看自己提交的订单，不因选择销售员而放宽范围。
- 原有“客户评价只有管理员可见”规则不变；项目经理、销售员不得通过详情聚合接口或文件签名链接读取评价正文/附件。

## 当前代码及关键风险

1. `RoleCode` 与数据库种子只有四种角色；`UserManagementService.replaceRole` 已执行角色替换，但 `sys_user_role` 仅有 `(user_id, role_id)` 唯一键，数据库仍可给一人插入多个角色。`UserAccountService` 把多角色组成权限集合，`AuthService.UserInfo` 从集合推导主角色，这与新规则冲突。
2. PC `UserList.vue` 角色选项缺新角色；小程序 `auth-session.js` 只接受四种角色。PC `AuthService.passwordLogin` 仅允许 ADMIN，此规则继续保持，项目经理不开放 PC 登录。
3. `DealerAppointmentController` 类级别只允许 DEALER；预约幂等键按经销商计，`V10` 的订单来源 CHECK 仅允许 ADMIN/DEALER_APPOINTMENT。不能让 SALES 伪装成 DEALER 创建订单。
4. `OrderService.scopedQuery` 对未知角色回退为客户本人订单；项目经理在此会看不到全量。`WorkProgressService`、`FileService` 等还有独立的读取范围，需要同步，不能只放开订单表查询。
5. `AdminOrderDetailService` 聚合了客户评价且仅 ADMIN 可用。项目经理不得复用此接口直接放权；需要不含评价的只读 DTO/接口。
6. 当前 PC `OrderForm.vue`、小程序 `dealer-booking.vue` 都没有销售员选择；订单列表和详情也没有销售归属字段。

## 实施顺序

### 1. 数据与单角色约束

- 上线前查询历史多角色账号：`SELECT user_id, COUNT(*) FROM sys_user_role GROUP BY user_id HAVING COUNT(*) > 1`。若有结果，先由业务确认保留哪一个角色，不按优先级静默合并或扩权。
- 新 Flyway 迁移插入 `PROJECT_MANAGER`、`SALES`，并在清理历史冲突后对 `sys_user_role.user_id` 加唯一约束；旧 `(user_id, role_id)` 可保留。服务层 `requireActive` 对非单一角色拒绝授权，新增/编辑用户始终替换唯一角色。
- `work_order` 新增可空 `sales_user_id`、外键与索引。历史订单为 `NULL`；不要把 `created_by` 当作指定销售员。
- 销售预约来源新增 `SALES_APPOINTMENT`，同步更新订单来源/待派单 CHECK。销售员预约幂等键单独按创建人作用域保存；不要复用语义为“经销商”的字段。保留旧经销商接口和旧订单兼容。

### 2. 后端契约与权限

- `GET /api/v1/users/sales?keyword=&page=&pageSize=` 提供启用、审核通过、非黑名单的 SALES 候选；首屏列出已有销售员，人数较多时提供搜索及分页/继续加载，不能因固定上限遗漏可选人员。对非管理员只返回 ID、显示名、必要的脱敏信息。候选不可由前端伪造，写订单时再次校验。
- 管理员订单创建/编辑请求加可空 `salesUserId`；经销商预约及新销售预约请求也加可空 `salesUserId`，纳入幂等摘要。同一 requestId 仅完全相同内容可重试，变更指定销售员须冲突。
- 订单响应返回 `salesUserId`、销售员显示名与准确的 `orderSourceLabel`。未指定时显示“未指定”，不自动绑定创建人。销售员即便选了另一位销售员，仍作为创建人保留自己的订单读取权。
- 项目经理仅允许 GET 全量订单列表和专用只读详情；专用详情可含订单、施工进度、耗材申请，但不能含客户评价。所有写接口由 Spring 权限和服务层同时拒绝，不能依赖 UI 隐藏。
- 扩展订单附件、施工进度和相关文件的**只读**签名授权：项目经理可看订单允许的附件；销售员仅能看自己创建或被指定订单的附件；`REVIEW` 文件永远只给 ADMIN 读。写权限不随读取权限扩张。
- JWT 过滤器现已在每次请求重载数据库角色，角色变更后旧 token 应立即按新角色生效；需补测多角色脏数据及角色变更后的拒绝/放行。

### 3. PC 与小程序

- PC 用户管理新增两个角色单选项、筛选标签和校验。非 ADMIN 无 PC 账号密码；项目经理仅手机号微信登录。PC 管理员订单表单增加可搜索销售员字段（允许清空），订单列表/详情展示指定销售员与创建来源。
- 小程序将 SALES、PROJECT_MANAGER 加入会话角色映射；预约入口支持 SALES/DEALER，共用表单字段校验、上传和重试锁定，提交接口按自身角色分流。预约表单的“销售人员（选填）”使用同一可搜索下拉组件，初始加载平台可用销售员，选项展示姓名及必要的脱敏区分信息；支持清空、加载中、空列表、加载失败重试，不把加载失败误判为必填。
- 项目经理的小程序订单页只读：可以查全量、筛选、进入详情与查看允许的附件；不渲染新增、编辑、确认、备货、评价、上传等写控件。对深链或意外点击写入口统一 `uni.showModal({ content: '无操作权限' })`；后台返回 403 时不误判为登录失效。
- 角色判断按唯一 `role`，`roles` 只为兼容旧响应；两者不一致或多角色时拒绝会话，不做权限并集。
