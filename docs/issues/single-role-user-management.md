# 全栈：单角色约束与项目经理、销售员用户管理

## 目标

- 新增 `PROJECT_MANAGER` 和 `SALES` 两种独立角色。每个用户只能有且只有一个角色，不做多角色权限并集。
- PC 管理员可新增、查询、编辑/指定这两种角色，并按既有账号生命周期管理；项目经理仅通过小程序手机号登录，不开放 PC 密码登录。
- 后台用户管理的“删除”采用经确认的软删除，使登录立即失效，历史订单不级联删除；最后管理员不可删除。

## 技术范围

- 上线前排查历史多角色账号；迁移角色字典并对 `sys_user_role.user_id` 加唯一约束，遇到冲突必须先人工定角色，禁止静默扩权。
- `RoleCode`、账号读取、登录响应、用户创建/更新、单角色校验与审计全链路更新；旧 token 下一请求立即按当前数据库角色鉴权。
- PC 用户列表、详情、角色筛选、表单、状态/黑名单/软删除入口统一角色标签和权限提示；手机号已存在时编辑原用户而不是新建重复账号。
- 销售员存在未结束的被指定订单时，改角色、停用、拉黑、软删除应要求先重派或清空订单归属；历史订单保留。

## 验收

新增和编辑两种角色可查可回显；一个用户无法持有多个角色；非管理员不能调用后台用户接口；旧 token 角色变更立即生效；最后管理员保护、手机号冲突、软删除和关联订单阻断均有后端集成与 PC 流程测试。
